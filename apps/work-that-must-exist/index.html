Your desired end state

Installed and accepted

Every requested unit needs installation and an inspection record. All temporary access must be removed before handover.

What is supplied to the model?

Two units begin uninstalled and available at the workface. The site starts clear. A shared gantry serves either unit; a trolley is set up and removed separately for each unit. Inspection needs an installed unit and suitable access still present. It represents a successful inspection and an acceptance record; failure and rework are outside this model. Access and method permissions remain fixed during a run.

Each action costs one step. Shortest means fewest actions, not least time, money or risk. Durations, crews, safety and physical feasibility are outside this model.

What survives a smaller scope?

The comparison below always uses the same access and methods with both units requested. Shared work retains one identity when B is removed.

What does “must” mean?

For each chosen action, the solver forbids it and searches again. If another successful route exists, that action is method-dependent. If none exists, it is unavoidable in this model.

Both methods still require temporary access. A particular setup action can be avoidable even when the broader function it serves is necessary.

This tests grounded actions against the declared methods. It does not establish necessity in every possible real project.

Four different relationships

A product is not a process.

A product structure describes physical things. A work breakdown groups the processes needed to deliver them. A process can change a product, use temporary equipment and produce evidence. “Is part of”, “contributes to”, “uses” and “produces” mean different things.

These views interpret this brief’s declared model. Select an item to follow its computed support. The process descriptions are proposed work, not records of work performed.

One route, more than one useful decomposition

A plan does not determine a unique WBS.

Change the packaging rule. Each action is owned once; cross-package support remains visible. These are two supplied organisational choices, not a discovered best organisation.

Which typed obligations came from this brief?

The completion profile is explicitly authored domain knowledge. Scope chooses the local objects to which it applies. The ontology does not discover engineering requirements from their names.

Where the meaning comes from

The foundational layer distinguishes objects, processes, qualities and information. The domain layer classifies a requested installation as a unit that needs acceptance evidence. Explicit domain methods and local access and handover rules supply the bridge from those meanings to actions.

The Turtle file is compiled into the model used here. The compiler and rule provenance are inspectable. Merely naming something “equipment” does not tell a planner how to install it.

The comparison we can make

Planning parity is an informative result. The semantic route makes the origin of obligations and support links explicit; a PDDL application could add the same explanations. We have not measured human modelling effort or established that ontology is better.

Our process search is ordinary finite planning. This essay does not implement the functorial plan-transfer algorithm in the source paper.

The restricted result
The end state is a starting point. Methods supply the bridge.

      
01
Work can be generated.
With explicit initial facts, final obligations and permissible actions, search produces a route without being given a project task list. Shared setup and eventual removal arise through those rules.
02
Necessity is conditional.
Restrict access or remove a method and previously replaceable work can become unavoidable. Remove a goal and some work disappears; a shared prerequisite can remain.
03
Structure needs another choice.
Causal support does not uniquely choose responsibility or hierarchy. Two packaging rules preserve the same work and expose different interfaces.

      
What remains unproved
A complete WBS for a real tunnel. Automatic discovery of engineering methods. Real safety, resources, time and cost. Full OWL reasoning or general PDDL support. A measurable productivity gain from ontology. Those would each require additional evidence.
